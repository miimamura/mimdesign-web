すべて**デバイスモックアップ**（実画面を機材にはめ込んだ合成画像）です。生のスクリーンショットではありません。

| ファイル | 実寸 | 比率 | 容量 | 用途 | 出典（元ファイル名） |
|---|---|---|---|---|---|
| `works/corporate-chocolatedesign.webp` | 1200×800 | 3:2 | 55KB | コーポレートサイト制作（CHOCOLATE DESIGN COMPANY）。§5.1 の4本目 | `public/images/works/vd.webp` |
| `works/seitai-takeuchi.webp` | 1200×800 | 3:2 | 54KB | 治療院サイトリニューアル（鵠沼たけうち整体院）。§5.1 の2本目 | `assets/img/seitaiin.webp` |
| `works/farm-fujimoto.webp` | 1117×745 | ≈3:2 (1.499) | **37KB**（WebP 化） | 農園サイトリニューアル（ふじもと農園）。§5.1 の3本目 | `assets/img/fujimoto.png` |
| `works/rentacar-campingcar.webp` | 1200×800 | 3:2 | **109KB**（WebP 化） | レンタカー予約サイト。**§5.2 の別枠**（メイン4本ではない） | `assets/img/camp.jpg` |

### レイアウト上、先に知っておくべきこと

**① 4点中3点は 1200×800（3:2）で揃っている。**
`farm-fujimoto.png` も 1117×745 = 1.499 で実質同じ比率です。**4点を 3:2 のグリッドで並べても、トリミングによる破綻は起きません。** ここは素直に組めます。

**② ただしモックアップの「型」が揃っていない。**

| ファイル | モックアップの種類 | 背景 |
|---|---|---|
| corporate / seitai / rentacar | ノート PC＋スマホ（seitai と rentacar は同一テンプレート） | 白 → 木目のデスク |
| farm-fujimoto | **外付けモニター単体**（Dell、キーボード見切れ） | 白い壁・白デスク |

3点は「白背景＋木目デスク」で揃っていますが、**`farm-fujimoto` だけ構図・機材・トーンが違います。**
4枚を同じサイズで並べると、ここだけ浮きます。対処の選択肢：

- カード内で**同じ比率にトリミングして画面部分だけを見せる**（モックアップの機材を見せない方向に統一する）
- 画像に**共通の枠・余白・背景色**を与えて、差を構図ではなくフレームで吸収する
- `farm-fujimoto` だけ扱いを変える（例：横幅いっぱいで1点だけ大きく見せる）

**③ 現行サイトの4本と、ブリーフ §5.1 の4本は一致していません。**

現行サイト（`front-page.php`）の Works は **コーポレート／整体院／農園／レンタカー**。
ブリーフ §5.1 のメイン4本は **介護・福祉／治療院／農園／コーポレート**、レンタカーは §5.2 の別枠。

→ **差分は「介護・福祉」が増え、「レンタカー」がメインから別枠へ降りたこと。**
介護・福祉の画像は手元にありません（§4-A）。

## 2. ブランド・About（3点）

| ファイル | 実寸 | 比率 | 容量 | 用途 | 出典 |
|---|---|---|---|---|---|
| `brand/mimdesign-logo-white.svg` | viewBox 500×100 | 5:1 | 2.9KB | ロゴ。ヘッダー／フッター。**ベクターなので拡大自由** | `assets/img/mimdesign_logo.svg` |
| `brand/favicon.webp` | 49×49 | 1:1 | 3.3KB | favicon | `assets/img/favicon.webp` |
| `about/profile.png` | 800×869 | ≈11:12（**縦長**） | 456KB | About セクションの本人写真 | `assets/img/profile_img.png` |

### 注意点

**ロゴは白一色（`fill: #fff`）です。**
SVG 内のスタイル定義が `.st0 { fill: #fff; }` のみで、**白背景に置くと完全に消えます。**
既存サービスサイトが紺ベタ塗りの上にロゴを置く前提だったためです。

ポートフォリオは §4.1 で**「白／オフホワイト中心・紺は文字色と罫線に限定」**と決まっているので、
**紺（または文字色）版のロゴを用意する必要があります。** SVG なので `fill` の値を差し替えるだけで作れます（`currentColor` にしておくと CSS 側で制御できて運用が楽です）。

**プロフィール写真は縦長（800×869）で、背景が白飛びしています。**
白／オフホワイト基調のサイトとは相性が良く、**背景を切り抜かなくてもそのまま馴染みます。**
ただし横長のスペースには入りません。About は**縦長の画像を前提にした組み**にしてください。

**favicon は 49×49 という半端な奇数サイズです。**
16/32/48/180（apple-touch-icon）へリサイズすると端数が出て、1px のにじみが残ります。実用上は許容範囲ですが、気になるならロゴ SVG から書き出し直すのが確実です。

## 4. 判断が必要なこと

### A. 介護・福祉サービス企業サイトの画像がない

§5.1 のメイン4本の**1本目**です。画像が手元にありません。選択肢：

1. 画像を提供してもらう（お手元にキャプチャがあれば最短）
2. STUDIO 版に掲載されているなら、**その画像の URL を教えてもらえれば取得できます**（GCS は疎通可能）
3. この1本だけ**テキストカードとして組む**（画像なしでも成立するレイアウトにする）

※ 3 を選ぶ場合、**レイアウト設計の前に決める必要があります。** 4枚グリッド前提で組んでから1枚欠けると、組み直しになります。

### B. STUDIO 版の画像をどうするか

サイト本体が取得できないため、**掲載画像の URL が分かりません。**
ブラウザで STUDIO 版を開いて画像を右クリック保存 → このリポジトリに置いていただければ、インベントリに追記します。
URL の一覧をいただく形でも取得可能です。

### C. VANILLABEANS 販促制作物 9点（§5.4）

ケーススタディ第2幕のギャラリーに使う想定の9点が未取得です。
第2幕は数字のない唯一の幕で、**制作物が並ぶこと自体が「5年間つくり続けた」の証明**という設計なので、
ここが空だと第2幕の構成が変わります。**入手の見込みを先に確認させてください。**

### D. Works の before / after 画像は存在しない

`mimdesign-next` のソースは `ec-before.webp` / `farm-after.webp` などを参照していますが、
**実ファイルはリポジトリにも Git 履歴にも存在しません。** before/after 比較を見せる構成は、現状の手持ちでは組めません。

## 5. 元リポジトリで見つかった不具合（参考）

移行元 `miimamura/mimdesign-next` に、**画像の取り違えがあります。** 新サイトに持ち込まないよう記録しておきます。

`fix: replace symlinks with real image files for Vercel compatibility` のコミットでシンボリックリンクを実体化した際、**参照先を取り違えたまま固定されています。** MD5 が一致＝中身が完全に同一です。

| ファイル名 | 中身の実体 | MD5 |
|---|---|---|
| `public/images/works/ec.webp` | **整体院の画像**（EC の画像ではない） | `5d2bedc1` |
| `public/images/works/farm.webp` | **`fujimoto.png` そのもの**（拡張子は .webp だが中身は PNG） | `fce8a458` |
| `public/images/works/rentacar.webp` | **`camp.jpg` そのもの**（拡張子は .webp だが中身は JPEG） | `61015fe1` |

結果として、`content/works/corporate-chocolatedesign.mdx` の `thumbnail: "/images/works/ec.webp"` は
**コーポレート案件のカードに整体院の画像を表示します。**

**本インベントリでは、MD5 で重複を排除し、中身に合った名前を付け直したうえで取り込んでいます。**
上表の3ファイルは重複なので、新リポジトリには含めていません。

その他：

- 履歴から削除された `public/images/works/vd.jpg` は、**中身が `vd.webp` と完全に同一**（`d495a505`／拡張子 .jpg だが実体は WebP）でした。**失われた画像はありません。**
- `public/` 直下の `next.svg` / `vercel.svg` / `window.svg` / `globe.svg` / `file.svg` は **Next.js のボイラープレート**なので取り込んでいません。

## 9. 切り出し画像のベゼル除去（2026-09-13）

モックアップから画面部分を切り出した際、**モニター／ノート PC のベゼル（黒枠）が残っていた。**

| ファイル | 削った量 | 変更後 |
|---|---|---|
| `farm-fujimoto-screen.webp` | 上6px・**右9px** | 657×374 |
| `corporate-chocolatedesign-screen.webp` | 上6px・下2px | 692×434 |
| `seitai-takeuchi-screen.webp` | 上6px・左2px | 700×436 |
| `rentacar-campingcar-screen.webp` | 上6px | 702×436 |

### 検出を一度外した理由（記録）

最初は**各辺の最外列／行の明度**だけを見て切り詰めたが、`farm-fujimoto` の右側は
**最外の2列が明るく、その内側の3〜8列目が黒**という並びだった（ベゼルの外にモニター筐体のハイライトがあるため）。
端だけを見る方式では検出できない。

**端から22px以内を走査し、最も内側にある暗い線の1つ内側まで削る**方式に変更して解消した。
4点すべてで、端22px以内に明度60未満の線が残っていないことを確認済み。

再切り出しは**元のモックアップから**行っている（圧縮済みの切り出し画像を再圧縮しないため）。
寸法が変わったので、`index.html` / `works.html` / `work-farm.html` / `work-corporate.html` の
`width` / `height` 属性も実ファイルと一致するよう更新した（ズレるとレイアウトシフトの原因になる）。
