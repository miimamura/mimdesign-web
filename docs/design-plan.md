## 1. カラートークン（6色）

§4.1「紺は文字色と罫線に限定。面では使わない／白・オフホワイト中心」を満たす。

| トークン | 値 | 用途 | 白地コントラスト |
|---|---|---|---|
| `--paper` | `#FFFFFF` | ベース面 | — |
| `--paper-alt` | `#F1F4F9` | 沈める面（表のヘッダ行、引用、注記） | — |
| `--ink` | `#0B1E5B` | 見出し・本文・構造罫線 | **15.5:1** |
| `--ink-muted` | `#5C6A8A` | 担当範囲・出典・注記 | **5.4:1** |
| `--rule` | `#C8D2E6` | 細罫（表の内側、ブロック境界） | 装飾罫のみ |
| `--accent` | `#A34A28` | 「現在」マーカー、フォーカスリング | **5.9:1** |

### 決めた理由

**`--ink` は既存サイトの `--navy-blue` をそのまま継承。** 値を動かすと §4.1 の「同じ家族に見える」が崩れる。`--paper-alt` も既存の `--offwhite` と同値。**継承は色を作り直さないこと自体で示す。**

**面に使う色は白とオフホワイトの2つだけ。** 既存サービスサイトは濃紺ベタ（`--deep-navy #050816`）の上に白文字を載せる構成なので、面の色を反転させるだけで別サイトに見える。§4.1 の差別化はここで効く。

**アクセントは錆色（`#A34A28`）。** 既存サイトのアクセントはネオン系3色（`#2563FF` / `#31D7FF` / `#FF6B9F`）。**この3色から最も遠い方向＝低彩度の暖色**を選んだ。青系を選ぶと既存サイトの縮小版に見える。

**オフホワイト地でも AA を維持する。** `--ink-muted` は `--paper-alt` 上で 4.90:1、`--accent` は 5.34:1。表のヘッダ行など沈めた面の上でも通常テキストの AA（4.5:1）を下回らない。

**使わない色を明示しておく。** 成功＝緑、警告＝赤のような意味色は入れない。このサイトには「良い/悪い」を色で判定させる箇所がなく、増やすと §4.2 の「色数を増やさずに強さを出す」と衝突する。

## 2. タイポグラフィ

### 2.1 役割分担（§4.2）

| 書体 | 使う場所 | 使わない場所 |
|---|---|---|
| **Noto Sans JP** | FV コピー・全見出し・本文・表・ラベル | — |
| **Jost** | **数字のみ／グローバルナビ** | 見出しの上の英字ラベル（§4.2 で明示的に禁止） |

**Jost は数字だけに自動で当てる。** `@font-face` の `unicode-range` を `U+0030-0039` に絞って Jost を先に宣言し、フォールバックを Noto Sans JP にする。こうすると和文の中の数字だけが Jost になり、個別にマークアップしなくてよい。運用時に「ここは数字だから span で囲む」という判断が発生しない＝属人化しない（§5 の主張と実装が矛盾しない）。

**実装上の注意：** Jost は幾何学サンセリフで x ハイトが高く、Noto Sans JP の従属欧文と並べるとベースラインと字面が揃わない。`size-adjust` / `ascent-override` での調整が必要。**ここは実装時に実機で合わせる工程を見込んでおく。**

**既存サイトは Inter を使っている。** Jost への変更自体が差別化として効く。

### 2.2 型スケール

| 役割 | モバイル | デスクトップ | 指定 |
|---|---|---|---|
| FV メイン | `min(46px, (100vw - 32px) / 14.6)` | 同左（46px で頭打ち） | Noto 700 / LH 1.5 / 字間なし |
| FV サブ | 15 | 17 | Noto 400 / LH 2.0 / **3行固定** |
| 幕見出し（H2） | 26 | 34 | Noto 700 / LH 1.5 |
| 節見出し（H3） | 19 | 24 | Noto 700 / LH 1.6 |
| 本文 | 16 | 17 | Noto 400 / **LH 1.9** |
| 表 | 14 | 16 | Noto 400（数字 Jost） |
| ラベル（課題／現在） | 13 | 13 | Noto 700 / 字間 .08em |
| メタ（担当範囲・出典） | 14 | 14 | Noto 500 / `--ink-muted` |
| ナビ | 14 | 14 | Jost 500 / 字間 .06em |

### 2.3 このスケールで重要なのは、比率ではなく2つの例外

見出し間は概ね ×1.4 だが、**その数字自体はどうでもいい。** 効いているのは次の2点。

**例外1：FV のサイズは文字数で決まっている。**

§3.1 は「メインをスマホで1行に収める」を要求している。和文は1文字＝1em なので、これはサイズの上限を機械的に決める制約になる。

**採用：読点なしの「使いやすさを成果まで届ける。」（14文字）**

| 画面幅 | サイズ上限（左右余白16px） |
|---|---|
| 320px（iPhone SE） | 20.6px |
| 375px | 24.5px |
| 390px | 25.6px |
| 414px | 27.3px |

指定は **`font-size: min(46px, calc((100vw - 32px) / 14.6))`**。

**当初 `clamp(20px, 6.4vw, 46px)` としていたが、実装して実機レンダリングで検証したところ 375px で2行に折り返した。** 原因は2つ。

1. **1文字＝1em で計算していたが、実際の送り幅は 1em より大きい。** 実測で和文書体のフォールバックは **1.0151em/字**（Noto Sans JP 本体は 1.000em だが、Web フォント読み込み前はフォールバックで組まれるため、広いほうに合わせる必要がある）
2. **`letter-spacing: .01em` を当てていた。** 14文字ぶんで 0.14em 増え、これが折り返しの最後の一押しになっていた

対応として **字間を外し**、割る数を実測ベースの 14.6（1.0151em に約4%の余裕）にした。
Chromium で **280 / 320 / 360 / 375 / 390 / 414 / 430 / 600 / 767 / 768 / 1024 / 1280 / 1920px の13幅すべてで1行・横スクロールなしを確認済み。**
フォールバック書体で収まるため、Noto Sans JP に差し替わったあとはさらに余裕が出る（**入れ替わりの瞬間に折り返しが起きない**）。

読点ありだと 375px で 22.9px まで落ち、`palt`（約物半角詰め）を効かせて 24.5px に戻す必要があった。**読点を外した結果、`palt` への依存がなくなった。** 約物の詰め方はフォントのバージョンやレンダラで挙動が揺れるため、**依存が1つ減ったぶん指定として確実になっている。** `palt` は適用してもよいが、レイアウトの成立条件ではなくなった。

**結論として、FV は大きくできない。** 一般的なポートフォリオのヒーローは 40px 超だが、このサイトは 24px が上限。**FV の強さはサイズではなく、サブコピー3行のリズムと前後の余白で作るしかない。** これは §3.1 の指定（動詞3つのリズムを視覚のリズムにする）と方向が一致している。

**例外2：階層の一番下は、大きくならずに小さくなる。**

ケーススタディは `幕 → 3-1 → 課題/仮説/設計/成果/現在` の4階層ある。ここで 課題/仮説/設計 を見出しとして扱ってサイズを上げると、3-1 と潰れ合う。

**この層は本文より小さくし（13px）、太さと字間で立たせる。** サイズの階段を下に伸ばすのではなく、下端で折り返す。§4.2 の「色数を増やさずに強さを出す」は、サイズだけでなくウェイトと字間も使うという意味に取っている。

### 2.4 行長（§4.3）

本文 17px × 42文字 ＝ **本文カラム 720px**。これがレイアウトの基準寸法になる。
モバイルでは 375px 画面で約21文字。40〜45文字はデスクトップの目標値として扱う。

### 推奨：第1弾は案A。案Bは第2弾の候補として保留

理由は3つ。

1. **§11 が完成度より公開の早さを優先すると明言している。** B の追従は実機調整が要る。
2. **B の価値はケーススタディ1セクションにしか効かない。** 第1弾に入る5セクションのうち4つでレールが空になる。**空欄が「まだ作っていない」に見えるのは、このサイトでは致命的**（運用が続く形を作れる、が主張なので）。
3. **B は 1040px 未満で A に畳む。** つまり B は A の上に乗るデスクトップ専用レイヤーであり、**A を先に完成させることが B の前提でもある。** 順番として A が先。

## 4. このサイト固有の設計方針

他案件に流用できない、この原稿・この画像在庫でしか成立しない判断。

### 4.1 表が主役の視覚要素

**原稿4本すべてに表がある。**

| 原稿 | 表 |
|---|---|
| ケーススタディ | 会員制度の3層 |
| SaaS | AI の3原則 |
| 服薬管理アプリ | **服薬 × SaaS の対照表**（2本を結ぶ装置） |
| Approach | AI の工程別の使い方 |

ポートフォリオで表がこれだけ出るのは珍しい。しかも服薬の対照表は、制作メモで「ここは必ず残す」と指定された**構成上の要**。

→ **表のスタイルを最初に決める。** 紺の細罫のみ・塗りつぶしなし・ヘッダ行だけオフホワイト・数字は Jost。カード装飾より先に、表の組み方に時間を使う。

→ モバイルで3列の表は潰れる。**横スクロールさせるか、定義リストに組み替えるかを表ごとに決める必要がある。** 対照表は2軸の比較なので、崩すと意味が壊れる。ここは横スクロール固定。

### 4.2 「現在」ブロックを、全セクション共通の固定装置にする

§4.3 が名指しする、このサイトの主張の核。**位置・形・ラベルを固定して繰り返す。**

- 形：上下に紺の細罫のみ。左右の枠と地の塗りは持たない（カードにしない）
- ラベル：`● 現在`（● は `--accent`。**アクセントが出る唯一の場所**）
- 位置：各節の最後。**成果ブロックの直後に密着させる**

「成果」（数字）と「現在」（残っている事実）を別の見た目にする。前者は Jost の数字が立つだけ、後者は罫線で囲われる。**囲われているのは常に「残った」ほうだけ**、という規則を通す。

### 4.3 色が使えない分、強調は書体の切り替えで作る

紺1色＋アクセント1色、英字ラベル禁止。**太字以外の強調手段がほぼない。**

→ **数字が Jost になること自体を強調機構として使う。** `4.3 → 4.5` `10,000人` `1,100万円` `180%` `約4時間` `993円` — 成果はすべて数字で書かれている。和文の中で数字だけ書体が変わるので、色を使わずに視線が止まる。

→ 逆に、**SaaS と服薬管理アプリには数字が1つもない**（守秘・未ローンチのため）。この2本だけ強調機構が効かない。**ここは表と、短い断定文（「AI の出力を、信用させない」）を大きめに組んで持たせる。**

### 4.4 画像を主役にしない

インベントリの結論がそのまま設計制約になる。

- 案件画像は4点のみ。うち1点（農園）はモックアップの型が違い、並べると浮く
- **守秘の2本（SaaS・服薬）は画像ゼロが確定**（§8）。ここは文章と表しか置けない
- 介護・福祉、VANILLABEANS 販促9点は未取得

→ **画像ありきのグリッドを組まない。** 画像は本文の補助として、あってもなくても崩れない位置に置く。
→ 農園の1点は、モックアップの機材を見せずに**画面部分だけを同比率でトリミング**して型を揃える。

### 4.5 ロゴは紺版を作る必要がある

現行ロゴは `fill: #fff` の白一色。**白地に置くと消える。** SVG なので `currentColor` に書き換えれば CSS 側で制御でき、フッターで地を変えても同じファイルが使い回せる。

### 4.6 余白は均等にしない

英字ラベル（PROBLEM / SERVICE）を使わないと決めた以上（§4.2）、**セクションの切れ目は余白と罫線だけで作る。** 均等な余白では切れ目が立たない。

| 位置 | 余白 |
|---|---|
| セクション境界の前後 | 160px / 120px |
| 幕見出しの上 | 120px |
| 段落間 | 32px |
| **成果 → 現在** | **32px（密着させる）** |
| **現在 → 次の節** | **120px（開ける）** |

**「現在」の前を詰めて後ろを開ける。** こうすると「現在」は独立した項目ではなく、**その幕の締めの一拍**として読める。「つくった」で終わらず「残った」で終わる、という構造がそのまま余白になる。

### 4.7 第1弾はモーションを0箇所にする

§4.4 は「使うなら1箇所だけ」。**使わないことも選べる。**

第1弾では入れない。理由は §11（公開の早さ優先）と、このサイトの主張（誠実さ・運用性）に対して、動きがなくても何も損なわれないため。`prefers-reduced-motion` の分岐実装も不要になり、第1弾の実装量が減る。

**1箇所の枠は、第2弾のレイヤー上昇図のために取っておく。** 使うならサイトの中心的な主張（上昇）に使うべきで、装飾には使わない。

## 5. 点検：他のポートフォリオでも同じになる部分

上の案を「これは誰のポートフォリオでも同じことを書いていないか」で見直した。
**6点が該当したので作り直した。** 残したものは理由を添えた。

### 作り直した6点

#### ① グローバルナビ → 第1弾は存在するセクションのみ

**汎用だった点：** ロゴ左・ナビ右の固定ヘッダーに Works / About / Contact を並べていた。どのポートフォリオでも同じ。

**作り直した理由：** §11 で第1弾は **FV / Capability / Case Study / 現在の領域 / About・Contact**。**Works と Approach はまだ存在しない。** 存在しないセクションへのリンクを置けない。

**変更後：** 第1弾のナビは `Capability` / `Case` / `About` の3項目（Contact は後日の判断で不採用）。Works は第2弾で追加する。

**あわせて判明した論点（要判断）：** §4.2 は Jost を「数字とナビゲーション」に限定している。**ナビを和文（実績・経歴・連絡先）にすると Jost の出番が数字だけになり、指定の半分が空になる。** 英字ナビにすれば Jost の役割が成立する。§4.2 が禁じたのは「見出しの上に置く英字アイキャッチラベル」であって、グローバルナビの英字表記は別物と解釈した。**この解釈でよいか確認したい。**

#### ② 型スケール → 比率ではなく2つの例外を設計として提示

**汎用だった点：** 最初は「1.25 のモジュラースケール」として書いていた。すべてのポートフォリオで同じ。比率の数字自体は何も決めていない。

**作り直した理由：** このサイトのスケールで実際に効いているのは比率ではなく、**FV のサイズ上限が文字数で機械的に決まること**（§3.1 の1行制約）と、**階層の最下層がサイズを上げずに下げること**（4階層の入れ子）の2点。比率は背景でしかない。

**変更後：** §2.3 に書き換え。`palt` で読点を残したまま 24.5px に届く、という具体解まで詰めた。

#### ③ Capability の3カラムアイコングリッド → 工程スパイン

**汎用だった点：** アイコン＋見出し＋説明文の3カラム。スキルを並べる定番。

**作り直した理由：** §1 が判断してほしいことを**「要件整理から情報設計・画面設計・デザインシステム構築まで任せられるか」**と明文化している。**発注側が確認したい順序が原稿に書いてある。** それを崩してスキルの一覧にするのは情報設計として負け。

さらに、英字ラベル禁止（§4.2）の下でアイコンを置くと、アイコンが唯一の視覚的アクセントになり、**アイコンの質でサイトの印象が決まる。** 新規制作しない方針（§6）なので、既製アイコンを使うことになる。避ける。

**変更後：** アイコンなし。**工程を左から右（モバイルは上から下）に1本の線で並べ、各工程に担当範囲を書く。** §4.1 の表・罫線のスタイルをそのまま流用でき、新しい部品を作らずに済む。

#### ④ Works のカードグリッド＋ホバー浮き上がり → 罫線区切りのリスト

**汎用だった点：** 2カラムのサムネイルカード、ホバーで y 移動＋影。

**作り直した理由：** 3つある。

- **§4.4 がホバーの浮き上がりを含む定型モーションを避けるよう指定している**（既存の `mimdesign-next` の MDX にまさに「カードホバー時に y 軸移動 + シャドウ強調」と書かれており、そのまま持ち込むところだった）
- **影はグレーの面を増やす。** §4.1 の「白・オフホワイト中心／紺は面で使わない」と方向が逆
- **画像が足りない**（4点、うち1点は型違い、介護・福祉は画像なし）。カードグリッドは画像が揃っている前提の形

**変更後：** 全幅の罫線区切りリスト。1件＝タイトル／課題ベースの一文／**担当範囲**／小さなサムネイル（任意）。
**担当範囲を最も目立つ副要素にする。** §5.3 がこれを必須としている目的は「問い合わせ時の期待値ずれを防ぐ」＝営業上の実害を防ぐこと。**装飾ではなく機能なので、視覚的な優先度も上げる。** 画像が欠けても崩れない。

#### ⑤「余白をたっぷり取る」→ 不均等な余白の具体値

**汎用だった点：** 最初は「余白を十分に取り、呼吸を作る」と書いていた。何も言っていないのと同じ。

**作り直した理由：** 均等な余白は、**このサイトで一番伝えたい構造（つくった→残った）を伝えない。**

**変更後：** §4.6 の表。とくに**成果→現在を32pxで密着、現在→次を120pxで開放**という非対称。余白の量ではなく、**どこを詰めてどこを開けるか**を決めた。

#### ⑥ モーション1箇所 → 第1弾は0箇所

**汎用だった点：** 「控えめなアニメーションを1箇所に」。ブリーフが1箇所と言っているから1箇所入れる、という受け身の判断だった。

**作り直した理由：** §4.4 は「**使うなら**1箇所だけ」。使わない選択肢を検討していなかった。§11 の公開優先を踏まえると、**0箇所が最も速く、主張とも矛盾しない。** `prefers-reduced-motion` の分岐も不要になる。

**変更後：** 第1弾は0箇所。枠は第2弾のレイヤー上昇図に取っておく（§4.7）。

### 点検して、残したもの

| 項目 | 汎用ではないと判断した理由 |
|---|---|
| 紺＋白＋アクセント1色 | §4.1 の指定そのもの。選択の余地は**アクセントの方向**だけで、そこは既存サイトのネオン3色から最も遠い錆色を選ぶという固有の判断をしている |
| 1カラム＋罫線区切り（案A） | 形は汎用。ただし**採用理由が固有**（画像在庫4点・守秘2本が画像ゼロ・第1弾の速度）。同じ形でも、画像が20点あれば選ばない |
| 本文720px | §4.3 の40〜45文字指定から機械的に出た値。恣意性がない |
| 表を細罫で組む | §4.1 の制約下で表を4本組むと、ほぼこの形にしかならない。**ただし「表を最優先で設計する」という優先順位づけは固有**（普通のポートフォリオに表は出てこない） |

### 点検の結論

作り直した6点に共通していたのは、**ブリーフではなく「ポートフォリオというジャンルの記憶」から書いていた**こと。カードグリッド、アイコングリッド、ホバー、モジュラースケール、たっぷりの余白。どれもブリーフに書かれていない。

逆に、**原稿と画像インベントリから逆算した箇所（表が4本ある／画像が4点しかない／数字が2本のセクションに存在しない／FV が15文字）は、最初から固有だった。** §6.1-4 が「インベントリを見てからレイアウトを決めろ」と指示しているのは、おそらくこのことだと解釈している。

## 7. 改訂 v2（2026-09-13）

「全体がワントーンで退屈」「FV は元サイトに合わせたい」という指摘を受けた改訂。

### 7.1 FV を既存サービスサイトの処理に合わせた

`mimdesign.site` の `.hero` をそのまま踏襲した。

| | 元サイト | ポートフォリオ v2 |
|---|---|---|
| 背景 | `fv_bg.png` ＋ `rgba(5,8,22,.48→.72)` | **同じ**（WebP 化して 1414KB → 48KB） |
| 高さ | `100svh` | 同じ（`100vh` フォールバック付き） |
| 配置 | 中央寄せ・白文字 | 同じ |
| 見出し | `clamp(32px, 4.5vw, 56px)` / 800 / 字間 -.02em | `min(50px, (100vw-32px)/14.2)` / 800 / 字間 -.02em |

**見出しのサイズだけ元サイトより小さい。** 元サイトは `<br>` で3行に折っているが、こちらは §3.1 が1行を要求しているため上限が下がる。字間 -.02em のぶん詰まるので、v1 の 46px から 50px に上げられた。

### 7.2 §4.1 との関係（重要）

§4.1 は「**紺は文字色と罫線に限定。面では使わない**」と定めていた。**FV とフッターはこの原則から外れる。**

差別化の考え方を次のように整理し直した。

- **FV とフッターは、2サイト共通のブランドの署名として同じ処理にする**
- **§4.1 の原則は本文側に適用する** — 本文は白／オフホワイト地、紺は文字と罫線のみ

つまり差別化は「入口の見た目」ではなく「**本文の組み方**」で取る。中身を読み始めた瞬間から別物になる。

### 7.3 ワントーン解消のための5手

| # | 変更 | ねらい |
|---|---|---|
| 1 | FV とフッターを暗部にした | ページの上下を締める。読む部分が明るく挟まれる |
| 2 | **セクションの地色を切り替えた** | 下記のとおり、装飾ではなく区分けとして使う |
| 3 | **幕ヘッダーの番号を Jost で大きく（44/60px）** | 色を使えない分、書体切替で強さを出す。§4.5 がこのセクションにだけ許可している表現 |
| 4 | セクション見出しを 26/34 → **28/40px** | ジャンプ率を上げる |
| 5 | 表から縦罫と塗りを外し、**横罫だけ**にした | 紙面的になり、罫線の量が減って軽くなる |

**2 の地色は意味を持たせてある。**

| セクション | 地 | 理由 |
|---|---|---|
| Capability | オフホワイト | — |
| Case Study | 白 | 最も長い本文。最も読みやすい地に置く |

| About | 白 | — |

### 7.4 副次的に解決したこと

| 問題 | どう解決したか |
|---|---|
| **ロゴが白一色**（インベントリ §2） | FV とフッターが暗部になったので、**白ロゴがそのまま使える。** 紺版は本文側で必要になった時のために残置 |
| **幕4に年号がない**（layout-phase1 §4.3） | 大きな数字を**年号ではなく幕番号（01〜04）**にしたため、年号の有無に左右されなくなった。年号は小さな補助情報に降格。幕タイトルからは重複する番号を外した |

| `--ink-deep` | `#050816` | 既存サイトの `--deep-navy` |
| `--paper-invert` | `#FFFFFF` | — |
| `--muted-invert` | `#C7D2FE` | 既存サイトの `--pale-gray` |

**3色とも既存サイトからの継承値で、新しい色は1つも足していない。** 色数は増えたが、ブランドの色域は広がっていない。

## 11. 改訂 v5：成果を先頭へ、ヒストリーを圧縮、SaaS を実績へ（2026-09-13）

### 11.1 成果を「成果とヒストリー」の先頭に出した

数字（1万人／1,100万円／180%）を節の冒頭に置き、`.results--lead` で **32/40px** に拡大。
**色が使えないこのサイトでは Jost の数字が唯一の強調機構**なので、ここは思い切って大きく取っている。
社名・期間は数字の下に小さく添えた（主役は数字であって案件名ではない）。

### 11.2 ヒストリーを4列の階段に圧縮した

| | 変更前 | 変更後 |
|---|---|---|
| 形 | 縦4行（番号・レイヤー・幕タイトル・年号） | **横4列**（番号・レイヤー・年号） |
| 幕タイトル | トップに掲載 | **`case.html` に譲った** |

**右へ行くほど段を持ち上げて「担当レイヤーの上昇」を形にしている**（デスクトップ 60/40/20/0px、モバイル 36/24/12/0px）。
§4.5 が番号・年号による階段表現を許可しているのはこのセクションだけなので、その範囲内。

実装上の注意：`align-items: end` にすると各段が下端揃えになり **`margin-top` の段差が打ち消される。** `start` でないと階段にならない（一度これで踏んだ）。

### 11.3 SaaS・アプリを制作実績に加えた

**ブリーフの制作メモは「Works に入れると他案件と並列になり、いま一番見せたい領域が埋もれる」と警告していた。**
指示を受けて加えるにあたり、その警告への対応として**先頭に独立したグループとして置いた。**

```
制作実績
  現在進行中｜UI/UX・業務システム   ← 先頭。画面は出せないので文字だけ
    製造業向け BtoB SaaS
    BtoC 服薬管理アプリ
    （works.html にはさらに BtoB 在庫管理 Web アプリ）
      → 2本の設計判断を読む（now.html）
  Web サイト                        ← サムネイル3点
      → 制作実績をすべて見る（works.html）
```

Web サイト案件と**同じ並びに混ぜず、前に出す**ことで埋もれを避けている。守秘で画面が出せない点は各案件に明記した（「開発中のため画面非掲載」「登録ユーザー限定のため画面非掲載」）。

**副次的な効果：** 評価（§9 前段）で挙げた「UI/UX の実物が1点も見えない」「最も売りたい能力が埋もれている」という問題のうち、**位置の問題は解消した。** 画面が出せない点そのものは変わらないため、§6.2 の自作図が本丸である状況は継続。
