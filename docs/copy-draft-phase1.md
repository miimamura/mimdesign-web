全4本が指定の40〜60字に収まっている。

### 「画面設計」の代案（60字）

```
静止画では終わらせません。HTML/CSS/JavaScript でプロトタイプまで作り、
状態の変化を実際に確かめます。
```

**技術名を出すかどうかは、§10 と関わる判断。**

| | 採用案（技術名なし） | 代案（技術名あり） |
|---|---|---|
| 伝わること | 検証までやる人だと分かる | **手を動かせる人だと分かる。** 差別化は強い |
| リスク | なし | **§10 の懸念に触れる。** 実装込みの安い発注を呼び込みかねない |

§10 は「実装（コーディング）工程は基本的に受けない方針」「レンタカー案件の実装まで一貫を前面に出すな」と明記している。**Capability は Works より前に出る位置なので、影響はレンタカーのカードより大きい。**

→ **採用案（技術名なし）を推す。** 検証用プロトタイプの話は、SaaS セクション本文で既に具体的に書かれている（「HTML/CSS/JavaScript のインタラクティブプロトタイプとして実装しました」）。**読み進めた人には伝わるので、Capability で先出しする必要がない。**

```
2013年から11年間、チョコレートデザイン株式会社（VANILLABEANS）に在籍しました。
受注電話を取るカスタマーサポートから始まり、Webデザイン、最後はブランド

指定の200〜300字に収まっている（296字）。

**3段落構成にした理由：** 過去（11年）／現在／一貫していること。
**最後の段落がこのサイトの主張とつながる。** ケーススタディの締め（「扱う対象が変わっただけ」）と同じ論理を、About で先に short version として置く。読み手はケーススタディを読む前にこの構えを受け取る。

### 本文

要件が固まっていない段階でもかまいません。
何を作るかより先に、何に困っているかを聞くところから始めます。

公開して終わりにはしません。運用が始まってからの改善や、体制が変わった

関わらないことは別の話です。
                                                              ── 83字

［メールアドレス］
```

### 2段落目は §10 への対応

§10 が指摘した問題：Approach セクションは「自分が抜けても回る」を強みに置くが、裏返すと「継続発注が不要」と読める。

**最後の一文がその反転を明示的に打ち消している。**
「仕組みを渡すことと、渡したあとに関わらないことは別の話です。」
＝ 自走できる状態にすることと、関与を終えることは別、という宣言。

原稿4本に共通する締め方（「情報を分かりやすくすることと、分かった気にさせることは違います」等）と同じ型なので、文体も揃う。

### 控えめ版（66字）

```
公開後の改善や、運用を引き継いだあとの相談にも対応しています。
つくって終わりにはしないので、気になることがあれば声をかけてください。
```

採用案より柔らかいが、**§10 の反転を打ち消す力は弱い。** 採用案を推す。

### 対応範囲の明示（任意）

```
実装（コーディング）は、検証用のプロトタイプを除いて基本的にお受けしていません。
```

§5.3 が「担当範囲を必ず明記する。問い合わせ時の期待値ずれを防ぐため」としており、**同じ理屈は Contact にも効く。**
ただし Works のカードで各案件の担当範囲を書けば足りるとも言える。**Works は第2弾なので、第1弾のあいだだけ入れておく、という選択肢もある。**

→ **判断を仰ぎたい。** 入れると誠実だが、入口で断る形にもなる。
